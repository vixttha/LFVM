# External authorization integration — pre-production only

LFVM-FOUNDATION-AUDIT-001, task 1. The external verifier must be executed from trusted code outside candidate control. The new adapter validates a separately pinned policy (distinct owner and auditor Ed25519 public keys, exact repository/branch, scope/schema digests, trusted history tip, trusted branch head and approved workbook workflow blob). It verifies immutable Git candidate ancestry, exact archive blobs against actual materialized bytes, and independently fetched GitHub run/job/attempt/runner/step/log markers for every workbook test. Existing signed receipt primitives still verify scope, qualification and owner acceptance. This adapter is not wired into the active pre-build gate and cannot by itself release a spreadsheet. The future workbook workflow does not yet exist. An independently trusted caller must obtain the policy pin, keys, candidate repository objects and logs and invoke the new verify_candidate_authority adapter to connect it to the signed release verifier, with actual workbook-content inspection and history validation. No candidate can nominate its own trust roots.

No actual signing identities, trusted production policy, acceptance event or workbook workflow was created. The owner approved pre-production repairs only, not production workbook construction or acceptance. Synthetic tests exercise policy pins and rejected evidence; the immutable Git path is exercised in a temporary synthetic Git store with a positive inventory check and negative tampering check, and also rejects a missing store. Real candidate verification requires a real authorized candidate. No licensing change or branch protection imposed.
